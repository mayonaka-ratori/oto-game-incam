# 作業の締めと引き継ぎ

AGENTS.md の「完了条件と引き継ぎ」を毎回同じ手順で行う。commit と push はこのスキルでは行わない。

1. `git status --short` と `git diff --stat` で、この作業で触ったファイルを確認する。無関係な変更が混ざっていれば報告に書く。
2. 実装記録の置き場所を決める。
   - `docs/README.md` の「作業記録の一覧」で「現行の作業計画と実装記録」となっている文書の「実装結果」または「実装記録」の章へ、実装したもの、実装時に決めた値、検証結果を追記する。
   - 新しい計画や分析を始めた場合だけ、次の番号で文書を作り、一覧へ足す。仕様の正本（`01`〜`06`）へ複製しない。
3. `docs/README.md` 冒頭の箇条書きを更新する。更新日は今日の絶対日付。「実装先行状況」「次の作業」「次の判断」を今の状態に合わせる。SessionStart の hook がこの箇条書きを毎回そのまま次のセッションへ渡すので、古い内容を残さず、各項目を2〜3文に収める。詳細は作業記録の文書と章へのリンクで済ませる。
4. 内容を変えた文書の冒頭にある「更新日」「ステータス」を合わせる。`03` の「0. 現在地」がフェーズやステップの変更に追随しているか見る。
5. 文書を変えた場合は `doc-consistency-checker` エージェントを呼び、変えた文書の名前を渡す。指摘があれば直す。表記だけの指摘は残してよいが、報告に書く。
6. 検証結果を集める。この作業で `src/` `tests/` `e2e/` `build/` を触っていれば `npm run typecheck` と `npm run test`。UIを触っていれば `npm run test:e2e`。この会話ですでに通した検証は、その後に変更がなければ再実行せず結果を引用する。走らせていない検証は「未実施」と理由を書く。実機（iPhone Safari、Android Chrome）は自動化できないので必ず「未実施」か実施日を書く。
7. 報告は次の順で、非エンジニアにも分かる日本語で書く。
   - 何を変えたか（利用者にとって何が変わるか）
   - 検証結果（通った / 失敗 / 未実施）
   - 残る未決事項と次の一手
   - 触ったファイルの一覧
   - commit は依頼があれば行う旨を一言
