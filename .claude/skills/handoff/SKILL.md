# 作業の締めと引き継ぎ

AGENTS.md の「完了条件と引き継ぎ」を毎回同じ手順で行う。commit と push はこのスキルでは行わない。

1. `git status --short` と `git diff --stat` で、この作業で触ったファイルを確認する。無関係な変更が混ざっていれば報告に書く。
2. 実装記録の置き場所を決める。
   - 現在の作業計画文書（`docs/README.md` の「実装先行状況」が指す文書。2026-09-14時点では `13`）の末尾の「実装記録」章へ、実装したもの、実装時に決めた値、検証結果を追記する。
   - 新しい計画や分析を始めた場合だけ、次の番号で文書を作る。仕様の正本（`02`〜`06`）へ複製しない。
3. `docs/README.md` 冒頭の箇条書きを更新する。更新日は今日の絶対日付。「実装先行状況」「次の作業」「次の判断」を今の状態に合わせる。SessionStart の hook はこの箇条書きをそのまま次のセッションへ渡すので、ここが古いと次の作業者が古い現在地で始める。
4. 内容を変えた文書の冒頭にある「更新日」「ステータス」を合わせる。`03` の「0. 現在地」がフェーズやステップの変更に追随しているか見る。
5. `doc-consistency-checker` エージェントを呼び、指摘があれば直す。表記だけの指摘は残してよいが、報告に書く。
6. 検証結果を集める。この作業で `src/` `tests/` `e2e/` `build/` を触っていれば `npm run typecheck` と `npm run test`。UIを触っていれば `npm run test:e2e`。走らせていない検証は「未実施」と理由を書く。実機（iPhone Safari、Android Chrome）は自動化できないので必ず「未実施」か実施日を書く。
7. 報告は次の順で、非エンジニアにも分かる日本語で書く。
   - 何を変えたか（利用者にとって何が変わるか）
   - 検証結果（通った / 失敗 / 未実施）
   - 残る未決事項と次の一手
   - 触ったファイルの一覧
   - commit は依頼があれば行う旨を一言
